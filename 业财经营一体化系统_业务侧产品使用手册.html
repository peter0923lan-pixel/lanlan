核心闭环：客户档案 → 合同与 SKU 明细 → 确认签约 → 人工确认生成回款计划 → 回款实际登记 → 收入实际确认 → 工作台/经营看板查看结果。

1. 角色与数据权限

角色数据范围主要可用操作限制
管理员全部数据全部业务操作；维护基础档案、组织、人员与权限；确认签约；删除收入实际被业务单据引用的档案不可删除
财务全部业务数据查看合同；维护回款计划；登记、编辑、撤销实际收入不参与合同确认签约；不可删除收入实际
商务销售负责人为本人新建、编辑、提交、确认签约合同；生成本人负责合同的回款计划销售负责人只能选本人；不能登记、调整收入实际或修改计划金额
商务助手本人录入或销售负责人为本人协助录入、编辑、提交、确认签约；可选择销售人员；查看本人范围内合同、回款与收入不能登记、调整收入实际或修改计划金额
数据归属口径：商务按合同“销售负责人”判断；商务助手按“本人录入或销售负责人为本人”判断。商务助手代录并指定销售负责人后，对应商务仍可查看。

2. 工作台首页

登录后默认进入“工作台首页”。页面将待处理事项、核心经营指标和高频入口放在同一屏，数据会随当前登录角色自动收口。

区域用途建议动作
今日待办汇总当前角色需要处理的合同、待判定业务类型、回款逾期、收入待确认点击卡片进入对应列表处理
核心指标概览展示已签合同额、MRR、ARR、当月回款/收入、逾期金额等用于日常经营巡检；点击“查看完整看板”进入经营看板
快捷入口新建客户、新建合同、登记到账、确认收入按角色权限显示；从这里进入高频动作

左下角显示当前登录人，可从该处退出登录。

3. 客户档案

3.1 新建与编辑客户

  1. 在左侧进入客户管理，点击“新建客户”。
  2. 至少填写客户名称；按实际情况补充简称、国家/地区、统一社会信用代码、行业、线索来源、客户整体状态等。
  3. 可选维护生态/直营、代理公司、渠道名称、企业微信 Corp ID、是否餐饮行业、健康状态与备注。
  4. 保存后，客户可在新建合同中被选择。
删除规则：客户已产生合同后不能删除；系统会提示“已在业务单据中使用，无法删除”。

3.2 查询、详情与导入

  • 列表支持按客户名称/简称关键词、行业、客户状态、线索来源、首签年度筛选。
  • “详情”打开客户全字段及金额概览；金额概览包括合同总金额、累计回款、累计确认收入和合同数量。
  • 点击“导入客户”后先下载 Excel 模板；严格按模板字段填写，再上传 .xls/.xlsx 文件。
  • 统一社会信用代码为空时，需填写特殊创建原因；导入发现重复客户不会覆盖原档案，可查看失败原因。
首签年度自动回填：客户首签年度为空时，合同确认签约后，系统会取该客户已签合同中最早签约日期的年份写入客户档案。

4. 合同台账与合同模板

4.1 合同全流程

1. 新建合同空白制单或选择本人模板
→
2. 基本信息客户、签约主体、成交模式、服务期
→
3. SKU 明细金额、付款规则、收入方式、服务期
→
4. 保存/提交草稿可持续编辑；提交后等待签约确认
→
5. 确认签约确认签约日期并触发回款计划确认

4.2 新建合同 - 基本信息

  1. 进入合同台账，点击“新建合同”。可选择“新建空白合同”，也可选择本人保存的合同模板。
  2. 填写客户、合同编号、合同名称、签约主体、业务类型（新签/续签/增购/待判定）、国内/海外、服务开始/结束日期、币种与合同汇率。
  3. 签约日期默认当天，可修改。它将作为付款规则选择“签约日”时的计算基准。
  4. 选择成交模式：直销时销售负责人必填；代理时代理公司必填；平台时平台主体必填。
  5. 点击“下一步”会直接进入 SKU 明细编辑页。

4.3 SKU 明细

  1. 点击“添加 SKU”，选择已启用的 SKU。
  2. 逐行填写数量、未税单价、税率、收入方式、服务开始/结束日期；系统自动计算不含税、税额和含税金额。
  3. 选择付款规则；可选填“支付宝/企微”。付款规则按 SKU 行配置，而非合同表头统一配置。
  4. 经常性收入、收入确认方式会默认带出 SKU 配置，必要时按业务实际调整。
  5. “保存草稿”可继续修改；“提交签约确认”后合同进入待签约状态。

4.4 状态与操作

状态含义可操作
草稿未提交签约确认编辑、删除、复制、存为模板、提交签约确认
待签约已提交，等待业务端确认商务、商务助手或管理员确认签约；可撤回后继续编辑
已签约签约日期已确认生成回款计划；可撤销签约（按权限）
  • 列表支持合同号/合同名/客户名关键词、状态、业务类型、签约主体、签约日期区间筛选。
  • 双击合同记录可查看合同表头和 SKU 明细；也可通过操作栏复制、编辑、提交/撤回、确认签约/撤销签约及生成回款计划。
  • “复制”会进入新建合同，带出原合同内容供修改；“存为模板”需要填写模板名称。
  • 合同模板按员工隔离：只能看到和使用本人保存的模板。

5. 回款管理

5.1 确认签约后生成计划

  1. 商务、商务助手或管理员在待签约合同上点击“确认签约”，核对并可修改签约日期。
  2. 系统弹出“是否立即生成回款计划”。选择“立即生成”后，在弹窗中确认计划明细；选择“暂不生成”可稍后处理。
  3. 已签约、尚未生成计划的合同，也可在合同操作栏或回款管理的“生成回款计划”入口选择生成。

5.2 付款规则与计划明细

付款规则类型生成方式业务提示
一次性生成 1 期，金额为 SKU 含税金额；基准日、相对付款天数、计划回款日均可在确认前调整管理员或财务可“拆分期次”；收入计划会按相同期数和比例同步拆分
按月按 SKU 服务期自动拆期，末期吸收尾差基准日为每月 1 日，结合相对付款天数生成计划日
按季按服务期覆盖的自然季度自动拆期，末期吸收尾差基准日为每季度首月 1 日
里程碑先生成一条待拆分记录手工选择基准日期、填写天数和比例/金额；填其中一个会计算另一个
比例口径：比例以 % 输入，例如输入 20 表示 20%；最后一期默认补足“100% - 前面期次比例合计”。

5.3 跟进、编辑、到账登记

  • 页面顶部显示当月计划回款、当月实际到账、逾期未回金额、未来计划回款。
  • 支持按合同号/客户名、计划状态和计划回款日期区间查询，并可导出 CSV。
  • 回款计划的比例、金额、删除和实际到账登记属于财务操作；已登记实际的计划不可编辑或删除。
  • 点击“登记实际”，填写到账日期、金额、汇率（外币必填）、银行流水号和备注。累计实际不能超过计划金额。

6. 收入管理

6.1 收入计划生成规则

合同确认签约时，系统为 SKU 生成收入计划。按月确认的 SKU 使用服务开始日作为每期确认日，不再使用自然月 1 日。

示例：服务期为 2026-08-10 至 2027-08-09、不含税金额 120,000 元、按月均摊确认时，系统生成 12 期：2026-08-10、2026-09-10 …… 2027-07-10；每期 10,000 元，合计严格等于 120,000 元。最后一期自动吸收小数尾差。

6.2 收入计划管理与确认

  1. 进入收入管理，先查看当月计划收入、当月已确认收入、累计已确认收入和待确认收入。
  2. 按合同号/客户名/SKU、状态、计划确认日期筛选对应计划。
  3. 财务或管理员点击“管理计划”，可修改计划确认日、计划金额并填写调整原因。
  4. 调整计划金额时，系统自动由同一 SKU 的末期计划吸收尾差，确保计划合计仍等于合同不含税金额；已登记实际收入的计划不可修改。
  5. 财务或管理员点击“登记实际”，填写实际确认日期、金额和备注。
  6. 计划实际累计达到计划金额后状态变为“已完成”；不足时为“部分完成”。

6.3 实际收入调整

  • 财务可在“管理实际”中编辑或撤销已登记记录；编辑、撤销必须填写原因。
  • 撤销会生成一条负数冲回记录，原始记录继续保留，计划金额和统计按净额重新计算。
  • 管理员额外可删除未撤销的错误正向记录，删除时必须填写原因。
  • 商务和商务助手仅可查看收入计划与实际结果，不能登记、编辑、撤销或删除。
  • 计划调整和实际登记、编辑、撤销、删除均记录操作人、时间、调整前后值与原因，可在审计日志中追溯。
收入与回款不同：回款记录的是资金到账，收入记录的是履约确认。两者可在日期和金额上不同，需分别登记。

7. 基础档案

基础档案由管理员维护，建议在开始录入合同前先完成必要配置。所有基础档案的删除均会校验是否已被业务单据引用；已引用时系统提示“已在业务单据中使用，无法删除”。

档案主要内容影响范围
SKU 管理SKU 编码、名称、业务大类、细分业务、默认税率、收入确认、经常性收入合同 SKU 明细、收入计划、MRR/ARR
付款规则规则名称、类型、基准日、相对付款天数、说明、状态合同 SKU 的回款计划生成
代理公司代理编码、名称、税号、默认佣金率代理成交模式合同
平台主体 / 签约主体主体编码、名称、统一社会信用代码、状态平台成交/合同签约主体
数据字典国家/地区、客户行业、线索来源、渠道名称、客户整体状态、业务大类、业务细分客户与 SKU 下拉选项；支持父级类型维护
角色/权限、组织架构、人员管理预置角色、部门上下级、账号、密码、是否销售人员菜单权限、销售负责人可选人员、数据范围

维护建议

  • 先维护数据字典中的业务大类/业务细分，再维护 SKU。
  • 付款规则修改后只影响后续新配置；合同 SKU 已保存的规则快照不会被历史修改直接覆盖。
  • 新增人员时，只有“是否销售人员”为“是”的启用人员，才会出现在合同的销售负责人下拉框。

8. 关键业务规则与常见问题

8.1 每次制单前检查

  • 客户档案已启用，且客户名称准确
  • SKU、付款规则、签约主体已在基础档案中启用
  • 成交模式与必填对象匹配：直销-销售负责人；代理-代理公司；平台-平台主体
  • SKU 服务期应位于合同服务期内
  • 合同编号、签约日期、服务期、含税/不含税金额已核对

8.2 常见提示处理

提示/现象原因处理方式
SKU 服务期间必须在合同服务期内合同模板带出的 SKU 日期与新合同服务期不一致可继续编辑并保存草稿；在提交签约确认前，调整 SKU 服务期或合同服务期
无权查看或操作该合同商务角色且该合同销售负责人不是本人由商务助手/管理员调整销售负责人，或使用对应销售账号登录
已在业务单据中使用，无法删除基础档案、客户、人员或字典项已经被业务数据引用保留记录并停用，或先处理关联业务单据
已有实际回款的计划不可编辑/删除计划已登记到账保留原计划，按财务调整流程补充记录；避免直接改写已发生数据
合同已签约但未生成回款计划确认签约时选择了“暂不生成”在合同列表点击“生成回款计划”，或从回款管理顶部入口处理

8.3 建议演示顺序

  1. 管理员确认基础档案（签约主体、SKU、付款规则、销售人员）已准备。
  2. 新建客户；再新建一份含 SKU 的合同并保存草稿。
  3. 提交签约确认；由商务、商务助手或管理员确认签约并生成回款计划。
  4. 在回款管理登记一笔实际到账；在收入管理登记一笔实际确认收入。
  5. 返回工作台和经营看板展示待办、回款、收入及指标变化。

9. 系统运行说明

系统按业务展示层、服务接口层与数据存储层划分职责。浏览器完成制单、查询和审批操作，业务接口集中处理权限、状态流转、金额校验与计划生成，数据统一保存在关系型数据库中。

层次职责
前端页面提供客户、合同、计划、基础档案和工作台的操作界面；按登录角色显示可用菜单与动作。
业务服务承载合同状态、数据权限、付款规则、回款/收入计划等业务规则，并提供标准接口。
数据存储使用 MySQL 保存主数据、业务单据、计划、实际记录和操作审计，保证关联数据一致性。
运行环境前端、后端和数据库以独立容器运行；通过统一配置启动，适合从本地演示环境迁移到服务器环境。

变更与上线节奏

  • 功能变更先完成业务规则确认，再进行开发、构建和本地验证。
  • 数据库结构变更通过版本迁移管理，随服务启动按顺序执行。
  • 镜像构建完成后可使用 Docker Compose 启动完整服务，环境参数通过配置文件统一维护。
  • 上线前建议完成角色权限、主数据、合同计划和统计口径的联合验收，再保留一次可回溯的数据备份。
